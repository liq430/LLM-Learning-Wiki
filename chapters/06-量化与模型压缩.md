### 6.1 量化基本原理

把 fp32/bf16 权重或激活映射到低位宽（INT8 / INT4 / INT1）表示。本节把数学与术语一次讲透。

#### 6.1.1 线性映射公式

**对称量化**（z = 0）：

```
   x_q = round( clamp(x / s, −Q_max, Q_max) )
   s = max(|x|) / Q_max        # 缩放因子
   dequant:  x ≈ s · x_q
```

- INT8 对称：Q_max = 127
- INT4 对称：Q_max = 7

**非对称量化**（含零点 z）：

```
   x_q = round( clamp((x − z) / s, 0, Q_max) )
   dequant:  x ≈ s · x_q + z
```

- INT8 非对称：Q_max = 255

#### 6.1.2 粒度（granularity）

| 粒度 | 元数据开销 | 精度 | 速度 | 典型场景 |
|---|---|---|---|---|
| per-tensor | 极少 | 差 | 最快 | 早期工作 |
| per-channel | 适中 | 中 | 快 | CNN 量化 |
| **per-group** | 多 | **高** | 中 | **LLM 主流量化（GPTQ / AWQ）** |

**per-group** 把一层的权重沿 channel 维分成若干组（group size=32/64/128），每组独立量化——精度接近 per-channel 但计算可向量化。

#### 6.1.3 对称 vs 非对称

- 对称：z=0，速度快，适合均值为 0 的权重；
- 非对称：适合激活分布偏斜（如 ReLU 后只有正数）——LLM 量化中权重通常对称，激活通常非对称。

#### 6.1.4 量化误差与信噪比

均方误差（理论精度度量）：

```
   MSE = E[ (x − dequant(x_q))² ]
```

经验准则：**8bit 量化一般无精度损失**；4bit 量化需要 group-size 64–128 + 校准补偿；2bit 量化难度极大。

### 6.2 PTQ vs QAT

#### 6.2.1 PTQ（Post-Training Quantization）

- **定义**：训练完后用少量校准数据（几十–几百条）统计激活分布，做一次性量化。
- **优点**：不需要重训、几分钟到几小时完成、对超大模型友好。
- **缺点**：精度上限低于 QAT；4bit 以下需要特殊算法（GPTQ / AWQ / SmoothQuant）。
- **主流工具**：GPTQ（AutoGPTQ）、bitsandbytes、AutoAWQ、SmoothQuant、llm-compressor。

#### 6.2.2 QAT（Quantization-Aware Training）

- **定义**：训练中插入伪量化算子（fake quantization），让模型适应量化误差。
- **优点**：精度更高（INT8 可达到 fp32 精度）。
- **缺点**：训练成本等同全参微调，大模型（>10B）极少使用。
- **代表**：TensorRT 的 QAT、Intel Neural Compressor。

#### 6.2.3 选型经验

| 场景 | 推荐 |
|---|---|
| LLM 4bit 部署 | PTQ + GPTQ / AWQ |
| LLM 4bit 微调 | QLoRA（NF4 + LoRA） |
| 边缘端 INT8 | PTQ 即可 |
| 极致精度（金融/医疗） | QAT |

### 6.3 主流算法逐个拆（面试按此序）

#### 6.3.1 LLM.int8()（Dettmers 2022）

**问题**：激活有**离群值维度**（outlier features）——少数 channel 数值远大于其他。

- 例：LLM 的某层激活值集中在 ±0.5，但有 0.1% 的 channel 达到 ±50；
- 直接 INT8 量化时，离群值把 scale 拉大，正常值被量化到 0 → 精度崩盘。

**方案**：**向量级混合分解（Vector-wise Quantization）**

```
   X_int8 · W_int8 = (X_outlier · W_fp16 + X_normal · W_int8)
```

- 对含离群维度的向量保留 fp16；
- 其余 INT8 量化；
- 三个矩阵加和即得结果。

**优点**：INT8 无损；**缺点**：推理时需要 hybrid kernel，开销比纯 INT8 大。

#### 6.3.2 GPTQ（Frantar 2022）

**核心思想**：基于 OBQ（Optimal Brain Quantization）的**逐层逐列量化 + 二阶（Hessian）补偿**。

- 思路：把一层权重量化看作带约束的重建问题 `min ‖W − Ŵ‖²_F s.t. Ŵ ∈ Q^d`；
- 量化一列时，用 Hessian 逆矩阵把误差**补偿到未量化的列**上，保持层输出分布；
- 用 Cholesky 分解加速，逐层完成。

**关键设定**：

- group size：通常 128（per-group 量化）；
- calibration set：约 128 条样本（来自 C4 / WikiText）；
- 4bit 单卡可量化 175B 模型（几小时）。

**优点**：精度高、显存省、实现成熟（AutoGPTQ）；**缺点**：校准数据敏感、长序列校准效果更好。

#### 6.3.3 AWQ（Lin 2023）

**核心洞察**：**量化精度应由激活分布决定**，而非权重分布。

- 观察：激活值大的 channel 更重要（"salient channels"）；
- 直接把这些 channel 的权重乘以 scale s，激活除以 s（**等价变换，输出不变**）；
- 缩放后，权重分布被压平，更易量化；
- 无需反向传播，校准即可。

**关键设定**：

- α（缩放强度）：搜索得到（grid search）；
- 量化粒度：per-group（128）；
- 通常与 GPTQ 相当或略优，**速度更快**（无需迭代补偿）。

#### 6.3.4 SmoothQuant（Xiao 2023）

**核心洞察**：把激活的离群**"平滑"迁移到权重**上，实现 **W·X 全 INT8**。

数学等价变换：

```
   Y = (W · diag(s)^-1) · (diag(s) · X)
     = W̃ · X̃
```

- 选择 `s_j = max(|X_j|) / max(|W_j|)`，让 X̃ 与 W̃ 的量化难度相当；
- 迁移后激活分布平滑、权重分布略增，但都能 INT8 量化。

**优势**：纯 INT8 推理，无需 hybrid kernel，速度比 LLM.int8() 快得多；**适合边缘 / 服务端部署**。

#### 6.3.5 QLoRA 的 NF4（已在第 4 章讲透）

- **信息论最优的 4bit 数据类型**：分箱边界为正态分布的分位数；
- **双重量化**：再量化缩放因子 s，省 0.4 bit/参数；
- **分页优化器**：Adam 状态用 NVIDIA 统一内存分页；
- 配合 LoRA 适配器 bf16 训练——24GB 消费级显卡可微调大模型。

#### 6.3.6 四种算法对比（必背）

![大模型量化四大算法：LLM.int8 / GPTQ / AWQ / SmoothQuant / QLoRA NF4](images/quantization_methods.png)

| 算法 | 核心洞察 | 量化粒度 | 适用 | 工程速度 |
|---|---|---|---|---|
| **LLM.int8()** | 离群维混合分解 | per-tensor | LLM INT8 推理 | 中 |
| **GPTQ** | 二阶补偿 | per-group 128 | LLM 4bit 部署 | 中 |
| **AWQ** | 激活感知缩放 | per-group 128 | LLM 4bit 部署 | **快** |
| **SmoothQuant** | 激活离群迁移到权重 | per-tensor/per-channel | LLM INT8 部署 | **快** |
| **QLoRA (NF4)** | 正态分位数分箱 | block-wise | LLM 4bit **训练** | 慢（需反量化） |

**面试一句话总结**：GPTQ 用二阶补偿、AWQ 用激活感知缩放、SmoothQuant 平滑离群、QLoRA-NF4 服务训练。

### 6.4 知识蒸馏

把"大模型（teacher）的知识"压缩到"小模型（student）"。

#### 6.4.1 经典软标签蒸馏（Hinton 2015）

```
   L = α · CE(student, 真值)
       + (1 − α) · T² · KL( softmax(student / T) ‖ softmax(teacher / T) )
```

- T：温度，>1 软化分布，传递更多信息（负样本概率也参与）；
- T²：补偿温度对梯度量级的影响。

#### 6.4.2 大模型时代的新形态：Data Distillation

直接用大模型的**输出当训练数据**训小模型：

- **Self-Instruct**（Wang 2022）：用 LLM 自生成指令数据微调小模型；
- **R1 蒸馏**（DeepSeek 2025）：DeepSeek-R1 生成 800K 高质量 CoT 数据 → 蒸馏 Qwen / Llama 7B/14B/32B —— 蒸馏后的小模型在数学/代码任务上逼近 o1-mini；
- **Alpaca / Vicuna / WizardLM** 等开源小模型都走这条路。

#### 6.4.3 蒸馏的多样性

| 蒸馏对象 | 蒸馏什么 | 适用 |
|---|---|---|
| **logits** | 输出分布 | 经典，需要 teacher 全 logits |
| **hidden states** | 中间层特征 | 跨架构需谨慎 |
| **attention** | 注意力图 | 适合视觉 Transformer |
| **data** | teacher 生成的回答 | **大模型主流** |

#### 6.4.4 蒸馏 vs 量化 vs 剪枝

| 方法 | 何时使用 | 优点 | 缺点 |
|---|---|---|---|
| 蒸馏 | 有充足 GPU 训 student | 性能上限高 | 训练贵 |
| 量化 | 只想省显存/加速 | 几小时搞定 | 4bit 以下需算法 |
| 剪枝 | 接受小幅下降 | 极致压缩 | 工程复杂 |

工程上**先量化后蒸馏**：先用 GPTQ 把基座量化到 4bit → 再用 LoRA 微调 + 蒸馏数据，混合方案通常效果最好。

### 6.5 剪枝与稀疏化

#### 6.5.1 两大类

| 类型 | 做法 | 硬件友好 | 大模型适用 |
|---|---|---|---|
| **非结构化剪枝** | 单权重置零（稀疏化） | ❌ 需要专用硬件 | 一般不用 |
| **结构化剪枝** | 剪整头/整层/整 FFN | ✔ 通用 GPU | ✅ 主流 |

#### 6.5.2 大模型稀疏化算法

| 算法 | 核心思想 | 关键论文 |
|---|---|---|
| **SparseGPT** | 一次性前向完成 50% 稀疏化，OBQ 风格补偿 | Frantar 2023 |
| **Wanda** | 用权重 × 激活统计量剪枝 | Sun 2023 |
| **LLM-Pruner** | 结构化剪枝 + LoRA 恢复 | Ma 2023 |

**Wanda 公式**（一句话）：

```
   importance(W_ij) = |W_ij| · ‖X_j‖
```

- 每行的 score = 权重幅值 × 该列激活 norm；
- 选 top-k 保留，其余置零；
- 不需要反向传播，一次前向完成。

#### 6.5.3 稀疏化 vs 量化的取舍

- **稀疏化**：理论压缩比高（50%+），但实际推理加速有限（除非用稀疏加速卡如 Cerebras / 国产 GPU）；
- **量化**：通用 GPU 直接受益（fp16→int8 速度近 2×），实际部署首选。

### 6.6 其他压缩手段

| 手段 | 思想 | 状态 |
|---|---|---|
| **低秩分解** | 把大矩阵分解为两个小矩阵 | 已被 LoRA 取代 |
| **参数共享** | ALBERT 跨层共享 | 精度有限 |
| **MoE 稀疏激活** | 每次只激活部分专家 | 已被工程化（Mixtral） |
| **Embedding 压缩** | 词向量量化 | 小模型常用 |

### 6.7 选型决策（按场景）

| 场景 | 推荐方案 | 预期压缩 |
|---|---|---|
| 大模型部署（GPU） | GPTQ/AWQ 4bit | 4× 显存、–30% 速度 |
| 大模型微调（消费卡） | QLoRA-NF4 | 24GB 跑 33B |
| 服务端极致性能 | SmoothQuant INT8 |–2× 速度 |
| 边缘/移动端 | SmoothQuant INT4 + 结构化剪枝 | 8× |
| 小模型压缩 | 知识蒸馏 | 精度保持–95% |
| 极致压缩（90%+） | 蒸馏 + 4bit 量化 + 剪枝 | 16× 综合 |

### 6.8 手算模板

#### 6.8.1 量化显存节省

**题目**：7B 模型 fp16 → INT4 量化，显存变化？

**解答**：
- fp16：7B × 2B = 14GB
- INT4：7B × 0.5B = 3.5GB
- 节省：10.5GB（75%）

#### 6.8.2 per-group 元数据开销

**题目**：4096×4096 权重矩阵，per-group 量化（group=128），INT8，per-group 缩放因子 1B。问总存储。

**解答**：
- 权重量化值：4096 × 4096 × 1B = 16 MB
- 缩放因子：4096 × (4096 / 128) × 1B = 4096 × 32 = 128 KB
- 总计：≈ 16.13MB（fp16 是 32MB，省 50%）

→ per-group 128 元数据仅占 0.78%，可接受。

#### 6.8.3 蒸馏温度梯度分析

**题目**：T=4 vs T=1，软化后梯度差异。

**解答**：
- T=4：logits 除以 4，分布更平 → 软目标概率差距变小 → 梯度更"柔和"；
- 但 `T²` 系数补偿：实际梯度量级不变，**收敛方向更鲁棒**；
- 经验：T=4–20 蒸馏效果最好。

### 6.9 面试题精选（20 选 8 高频）

#### 概念类

1. **为什么大模型量化难？** → 激活离群值 + 层间误差累积；LLM.int8/AWQ/SmoothQuant 都是针对性设计。
2. **GPTQ / AWQ / SmoothQuant 区别？** → 二阶补偿 vs 激活感知缩放 vs 离群平滑迁移。
3. **4bit 量化后为什么还能用？** → per-group 粒度 + 校准补偿 + 关键层混合精度。
4. **per-tensor / per-channel / per-group 区别？** → 粒度越细精度越高、元数据越多。
5. **对称 vs 非对称量化？** → z=0 对称快；非对称适合偏态分布。
6. **PTQ vs QAT 区别？** → PTQ 训练后量化几小时搞定，主流；QAT 训练成本高但精度更好。
7. **NF4 为什么适合 LLM 权重？** → 权重近似正态分布，NF4 按正态分位数分箱，信息论最优。
8. **稀疏化 vs 量化取舍？** → 稀疏化硬件依赖、量化通用 GPU 友好——大模型部署首选量化。

#### 工程类

9. **GPTQ 校准数据多少合适？** → 128 条样本足矣；用 C4 / WikiText 等通用文本。
10. **AWQ 比 GPTQ 更快的原因？** → 不用迭代补偿；一次 grid search 找 α。
11. **SmoothQuant 的 s 怎么算？** → `s_j = max(|X_j|) / max(|W_j|)`，对每个 channel 独立算。
12. **INT8 量化能把 7B 装进单卡吗？** → 是的，约 7GB（加上 KV cache 紧但可行）。
13. **蒸馏时温度 T 怎么选？** → T=4–20 是常见区间；T 越大软化越强。
14. **R1 蒸馏小模型是怎么做的？** → 用 R1 生成 800K CoT 数据 → SFT Qwen / Llama 7B-32B。
15. **SparseGPT 与 Wanda 区别？** → SparseGPT 用 OBQ 风格补偿；Wanda 用权重×激活幅值单次剪。
16. **MoE 是压缩吗？** → 不是；MoE 总参数不变但激活参数减少 → 推理 FLOPs 降低。

#### 综合类

17. **完整压缩 pipeline？** → GPTQ/AWQ 4bit 量化基座 → 蒸馏数据 SFT 小模型 → 评估 → 部署。
18. **量化会不会掉点？** → INT8 一般不掉；INT4 掉 1–5 PPL；INT2 困难。
19. **量化与蒸馏能组合吗？** → 能：先 GPTQ 基座 → 再 LoRA + 蒸馏数据 SFT。
20. **未来方向？** → 1bit / sub-bit 量化（如 BitNet b1.58）、原生 FP4/FP8 训练、可学习量化。

### 6.10 三句话总结

1. **量化是大模型部署的标配**——4bit + per-group + 校准补偿，能保留 95%+ 精度，省 75% 显存。
2. **GPTQ / AWQ / SmoothQuant 三足鼎立**——二阶补偿 / 激活感知 / 离群迁移，分别对应"权重补偿 / 等价缩放 / 分布平滑"三种哲学。
3. **蒸馏与量化组合**——R1 蒸馏 + 4bit 量化的小模型在多数任务上能逼近甚至超过大模型。
