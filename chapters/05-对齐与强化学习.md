### 5.1 RL 基础一条线

被问到"RL 在大模型里怎么用"，先把这五层基础按顺序摆出，面试官就能看到完整的认知地图。

#### 5.1.1 MDP（Markov Decision Process）

五元组 `(S, A, P, R, γ)`：

- **S**：状态空间（环境的全部可观察状态）
- **A**：动作空间
- **P**：状态转移函数 `P(s' | s, a)`
- **R**：奖励函数 `R(s, a) → r`
- **γ ∈ [0,1)**：折扣因子，未来奖励的衰减率

#### 5.1.2 价值函数与贝尔曼方程

定义**状态价值** `V(s) = E_π[∑_t γ^t r_t | s_0=s]`、**动作价值** `Q(s,a) = E_π[∑_t γ^t r_t | s_0=s, a_0=a]`。

**贝尔曼方程**（动态规划的核心递推）：

```
   V(s) = E_a~π [ R(s,a) + γ · E_s'~P [ V(s') ] ]
   Q(s,a) = R(s,a) + γ · E_s' [ E_a'~π [ Q(s', a') ] ]
```

#### 5.1.3 演进线（按时间）

| 阶段 | 关键思想 | 代表算法 | 解决的问题 |
|---|---|---|---|
| 表格 RL | 维护 Q 表 | Q-Learning | 小状态空间 |
| 深度 Q 学习 | 用 NN 拟合 Q | DQN | 高维状态 |
| 策略梯度 | 直接优化 π | REINFORCE | 连续 / 大动作空间 |
| Actor-Critic | 策略 + 价值 | A2C / A3C | 降低 PG 方差 |
| **PPO** | 裁剪 IS 比 | PPO | 训练稳定 + 实现简单 |
| 大模型 RLHF | 偏好学习 + PPO | InstructGPT | 对齐人类意图 |

#### 5.1.4 探索-利用

- **ε-greedy**：以概率 ε 随机探索、1-ε 选最优动作
- **大模型语境**：对应采样温度 τ（τ=0 贪心、τ 大则更"探索"）
- **RLHF 后期**：τ 通常退火到 0（聚焦 RM 高分回答）

#### 5.1.5 重要性采样（Importance Sampling）与 PPO 裁剪

**重要性采样**：用一个分布 p 的样本估计另一个分布 q 的期望：
```
   E_q[f(x)] = E_p[f(x) · q(x)/p(x)]
```

**问题**：当 p 与 q 差太远时，方差爆炸。PPO 的核心是**裁剪 IS 比**：
```
   r_t(θ) = π_θ(a_t | s_t) / π_θ_old(a_t | s_t)
   L_clip = E[min(r_t · A_t, clip(r_t, 1-ε, 1+ε) · A_t)]
```

- ε 通常 0.1–0.2
- 直觉：不让新策略与旧策略偏离太远，保证 IS 估计稳定
- 这是 PPO 比 vanilla PG 在 LLM 训练中能跑得稳的根本原因

### 5.2 RLHF 三阶段（InstructGPT，必考逐段讲）

OpenAI 的 InstructGPT（2022）奠定 RLHF 范式，三阶段流水线如下。

#### 5.2.1 阶段一 — SFT（已在第 4 章讲透）

- 人工写高质量 `(prompt, response)` 对，约 10K–100K 条；
- 标准 CLM loss，只对 response 部分算梯度；
- 得到 `π_SFT` —— 已经学会听话、但还不一定符合人类偏好的基策略。

#### 5.2.2 阶段二 — 奖励模型 RM

对同一个 prompt，生成 K 个回答（K=4–8），人工标注员**两两比较**哪个更好（pairwise ranking）。

**为什么用 pairwise 而不是打分？**
- 打分主观、跨样本难一致；
- 两两排序相对容易、Bradley-Terry 模型假设下与"潜在奖励"等价。

**Bradley-Terry 偏好模型**：

```
   P(y_w ≻ y_l | x) = σ( r(x, y_w) − r(x, y_l) )
```

- 假设每个回答有一个"真实奖励" r(x, y)；
- 两个回答的奖励差 → sigmoid → y_w 比 y_l 更受偏好的概率。

**RM 损失**：

```
   L_RM = − E_(x,y_w,y_l) [ log σ( r_φ(x, y_w) − r_φ(x, y_l) ) ]
```

- `r_φ` 通常以 `π_SFT` 初始化（最后一层换为标量头）；
- 训练数据规模 O(100K) 偏好对；
- 训练完后 RM 是一个**固定函数**，后面对 RL 步骤提供奖励信号。

#### 5.2.3 阶段三 — PPO 强化

把"让 RM 打分高"作为目标，用 PPO 微调 `π_SFT`：

```
   max_π  E_(x,y)~π [ r_φ(x, y) ] − β · KL( π ‖ π_SFT )
```

- 前一项：让 RM 打分高；
- 后一项：约束新策略不偏离 SFT 太远（防止 reward hacking）；
- β 是 KL 系数，控制保守程度（越大越接近 π_SFT）。

**为什么必须有 KL 约束？** RM 是不完美的代理，无约束的 π 会"钻空子"——典型 hack：输出冗长谄媚文本刷分；KL 把策略"拴在"人类示范分布附近。

### 5.3 PPO 的四模型与工程痛点

RLHF 阶段三需要 **4 个模型同时在显存**：

| 模型 | 是否训练 | 作用 |
|---|---|---|
| **Actor** π_θ | ✔ 训 | 被优化的策略 |
| **Critic** V_φ | ✔ 训 | 估计状态价值、计算优势 A_t |
| **Reward Model** r_φ | ✘ 冻结 | 提供奖励信号 |
| **Reference** π_SFT | ✘ 冻结 | 计算 KL 约束 |

#### 5.3.1 工程痛点（这是后来 DPO 出现的根本动机）

- **显存**：4 个同尺寸模型同驻显存，70B 模型根本跑不动；
- **训练不稳定**：PPO 在语言生成上对超参极敏感（KL 系数、学习率、批大小）；
- **数据效率低**：需要在线采样 rollouts，每条 prompt 需生成 K 个回答；
- **奖励 hacking**：RM 会被策略钻空子。

#### 5.3.2 PPO 目标函数（带 GAE 优势估计）

```
   L_PPO = E [ min(r_t · A_t, clip(r_t, 1-ε, 1+ε) · A_t) ] − c1 · L_VF + c2 · S[π]
```

- `r_t = π_θ(a_t|s_t) / π_θ_old(a_t|s_t)`：重要性采样比
- `A_t`：**GAE**（Generalized Advantage Estimation）估计的优势
- `L_VF`：Critic 价值回归损失
- `S[π]`：策略熵正则（保探索）

GAE 优势估计：

```
   A_t = ∑_{l=0}^∞ (γλ)^l · δ_{t+l}
   δ_t = r_t + γ · V(s_{t+1}) − V(s_t)
```

λ ∈ [0,1] 控制偏差-方差权衡。

### 5.4 DPO：把 RL 问题变成分类问题

**DPO（Direct Preference Optimization, Rafailov 2023）** 是 RLHF 之后最重要的算法简化——不训 RM、不做 PPO、不采样 rollouts，直接把偏好数据喂给策略模型做监督训练。

#### 5.4.1 推导（直觉版）

起点仍是 KL 约束的 RL 目标：

```
   max_π  E_(x,y)~π [ r(x, y) ] − β · KL( π ‖ π_ref )
```

对该目标关于 π 求最优解，可**解析求出**闭式最优策略：

```
   π*(y|x) = (1/Z(x)) · π_ref(y|x) · exp( r(x, y) / β )
```

反解 r：

```
   r(x, y) = β · log( π*(y|x) / π_ref(y|x) ) + β · log Z(x)
```

代入 Bradley-Terry 偏好模型，`β·log Z(x)` 项被分子分母消去，得到**DPO 闭式损失**：

```
   L_DPO = − E_(x, y_w, y_l) [
       log σ( β · ( log π_θ(y_w|x) / π_ref(y_w|x)
                  − log π_θ(y_l|x) / π_ref(y_l|x) ) )
   ]
```

简化表示：

```
   L_DPO = − log σ( β · [ Δ_log_θ(y_w) − Δ_log_θ(y_l) ] )
   Δ_log_θ(y) = log(π_θ(y|x) / π_ref(y|x))
```

#### 5.4.2 直觉

**提高"好回答相对参考模型的似然"，压低"坏回答相对似然"，差距拉大即可**。完全不需要 RM、不需要 Critic、不需要在线采样。

#### 5.4.3 工程优点

- 只需 2 个模型（policy + reference），显存减半；
- 训练方式等同 SFT，工程友好；
- 实现简单（十几行代码）；
- 效果与 PPO RLHF 相当甚至更稳。

#### 5.4.4 DPO 的局限

- **离线**：分布外探索弱，碰到训练集没见过的 prompt 表现下降；
- **β 敏感**：β 大则保守（接近 π_SFT），β 小则激进（容易崩）；
- **容易 reward hacking**：单纯的偏好学习也可能让策略走向奇怪模式（如"短回答高奖励"）；
- **不能与 RM 联合**：无法引入"必须是 JSON 格式""必须调工具"这类硬约束。

针对这些弱点有大量后续工作：

| 变体 | 改进点 |
|---|---|
| **IPO** | 加正则，避免 DPO 过拟合到偏好的 |
| **KTO** | 不需成对偏好，单点偏好即可 |
| **SimPO** | 无参考模型，更省显存 |
| **ORPO** | 把 SFT 与偏好合并到同一目标 |
| **DPO-Iterative** | 多轮 DPO + 在线采样，模拟在线学习 |

### 5.5 GRPO：去 Critic 的在线 RL

**GRPO（Group Relative Policy Optimization, DeepSeek-AI 2024）** 是 DeepSeek 团队对 DPO 的进一步简化——专为推理类任务设计，去掉 Critic，用**组内相对奖励**当基线。

#### 5.5.1 核心思想

对同一个 prompt，采样 G 个回答（通常 G=8–16），用组内奖励统计当基线：

```
   A_i = (r_i − mean(r_1, ..., r_G)) / std(r_1, ..., r_G)
```

再用 PPO-style 裁剪目标更新策略。**关键创新**：用组内相对值代替 Critic 学到的价值。

#### 5.5.2 GRPO 完整目标

```
   L_GRPO = − E_(x, {y_i}) [
       (1/G) · ∑_i [ min( r_i(θ) · A_i, clip(r_i(θ), 1-ε, 1+ε) · A_i ) − β · KL(π_θ ‖ π_ref) ]
   ]
```

其中：

- `r_i(θ) = π_θ(y_i|x) / π_θ_old(y_i|x)`：IS 比
- `A_i = (r_i − mean) / std`：组内优势
- 优势归一化（除 std）让不同 prompt 的梯度量级一致。

#### 5.5.3 GRPO 的工程优势

- **无需 Critic**：省一个模型，显存进一步降；
- **奖励可规则化**：对数学/代码题用"答案对/单元测试通过"判分，无需训练 RM；
- **组内采样**：G 个回答通常很短（推理任务），显存与延迟都友好。

#### 5.5.4 DeepSeek-R1：GRPO + RLVR 的范式

DeepSeek-R1（2025）把 GRPO 推到极致：

- **R1-Zero**：纯 RL（GRPO + RLVR）训基座 → 自然涌现长思维链、自检、反思等"推理能力"；
- **R1**：加少量冷启动 SFT 数据改善可读性，效果优于 R1-Zero；
- **核心洞察**：当奖励是**可验证**（数学对、代码通过），无需 RM，可避免 reward hacking。

| **ORPO** | ✘ | ✘ | ✘ | 2 | 低 | SFT + 偏好合并 |

### 5.7 相关概念（一句话级别）

- **RLAIF**（Anthropic 2023）：用 LLM 按原则生成偏好数据代替人工标注——RLHF 的可扩展版本。
- **Constitutional AI**（Anthropic）：用"宪法原则"做自我批评与改写 + RLAIF，减少人类标注。
- **PRM vs ORM**：过程奖励（逐步打分）vs 结果奖励（只看最终答案）——PRM 更精细但成本高、ORM 更便宜但信号稀疏。

### 5.8 2025 前沿：GRPO 家族与 RLVR 生态

本节是 **2025 算法岗最高区分度题**——把"GRPO 有什么问题 → 怎么改"答出层次感。

#### 5.8.1 RLVR（Reinforcement Learning with Verifiable Reward）

- **定义**：对数学/代码这类**有客观对错**的任务，用规则自动判分当奖励；
- **优势**：奖励免费（rule-based）、不可被 hack（标准答案固定）、训练稳定；
- **意义**：被 DeepSeek-R1 / o1 / Qwen3 / Kimi K1.5 等推理模型作为后训练标配；
- **行业术语**：被誉为「**第三条 scaling 路线**」——和"扩 N"（Chinchilla）、"扩 D"（数据）、"扩 RL 算力"并列。

#### 5.8.2 GRPO 的三个已知偏差

1. **长度偏差（length bias）**：按长度归一化会惩罚短的正确回答 → 模型"宁长勿对"；
2. **零梯度组浪费**：组内全对或全错时优势为 0，梯度无效；
3. **熵崩溃**：裁剪上界过低导致策略过快收敛到单一模式、丧失探索。

#### 5.8.3 2025 修复线（按"问题→修复"讲）

| 方法 | 修复问题 | 关键改动 | 效果 |
|---|---|---|---|
| **Dr.GRPO** | 长度偏差 | 序列级归一化（不按 token 数） | 短回答不再被惩罚 |
| **DAPO** | 零梯度组 + 熵崩溃 | 动态采样 + clip-higher | AIME 2024 上 50 分 |
| **GSPO** | MoE 训练不稳定 | token 级 IS 比改序列级 IS 比 | MoE 训练显著稳定 |
| **GMPO** | 训练不稳 | 组内优势用几何平均 | 进一步稳定 |

**DAPO 完整配置**（OpenRLHF / verl 已支持）：
- `clip_ratio_high = 0.28`（比标准 0.2 高）
- `dynamic_sampling=True`（过滤全对/全错组）
- `token_level_loss=True`
- `kl_coef = 0`（去掉 KL，靠 clip 与组内机制控漂移）
- `reward_overlong_penalty=True`（抑制冗长输出）

#### 5.8.4 奖励模型的进化

- **标量打分 RM**（InstructGPT 路线）：训练成本低，但易被 hack；
- **生成式评判 RM**（DeepSeek-GRM, RM-R1）：让 RM 先写批判推理再给分；
- **工具增强 RM**（Agentic Reward Modeling）：调用工具查证事实；
- **Process RM**（Math-Shepherd, OmegaPRM）：逐步打分，对推理任务关键。

#### 5.8.5 Self-Evolving RL（前沿了解）

让 Agent 自造任务自训：

- **Absolute Zero**（2025）：零外部数据，模型自生成编程题并自评；
- **WebRL**（2025）：从失败轨迹生成新任务；
- **配合课程学习**：difficulty filtering 保持训练在"能力前沿"——学到能学、最难不会。

#### 5.8.6 面试问法示范

- "GRPO 有什么问题？怎么改？" → 长度偏差/零梯度组/熵崩溃，分别对应 Dr.GRPO / DAPO 动态采样 / clip-higher。
- "GSPO 改了什么？" → token 级比值改序列级。
- "为什么 R1 训练后推理变强而通用能力不崩？" → 冷启动 SFT 数据 + KL 接近 0 + clip-higher 平衡探索。

### 5.9 手算模板

#### 5.9.1 Bradley-Terry 偏好概率

**题目**：RM 对 prompt x 的两个回答分别打分 1.2 和 0.4，问 y_w（高分）被偏好的概率。

**解答**：
```
   P(y_w ≻ y_l) = σ(1.2 − 0.4) = σ(0.8)
                 ≈ 1 / (1 + e^(-0.8))
                 ≈ 0.690
```

直观验证：logit 每增加 1，偏好概率从 50% 涨到–73%。

#### 5.9.2 DPO 损失量级

**题目**：对某个偏好对 (x, y_w, y_l)，当前策略的相对似然差 `log π(y_w)/π_ref(y_w) − log π(y_l)/π_ref(y_l) = 0.5`，β=0.1。求 L_DPO 与"需要多大调整才能使损失降到 0.1"。

**解答**：
- 当前 loss：`−log σ(0.1 × 0.5) = −log σ(0.05) ≈ −log(0.512) ≈ 0.670`
- 要 loss = 0.1：`σ(β · Δ) = 0.9` → `β · Δ = log(0.9/0.1) = 2.197` → `Δ = 21.97`
- 即：相对似然差要从 0.5 推到 21.97（logit 空间大幅拉开）

→ 直观：DPO 的损失数值**看起来很小，但梯度信号是按指数级放大**，训练并不慢。

#### 5.9.3 GRPO 优势估计

**题目**：对某 prompt 生成 8 个回答，奖励为 `{0.0, 0.2, 0.5, 0.6, 0.7, 0.8, 0.9, 1.0}`，求每个回答的归一化优势。

**解答**：
- mean = (0+0.2+0.5+0.6+0.7+0.8+0.9+1.0) / 8 = 4.7 / 8 = 0.5875
- var = Σ(r_i - 0.5875)² / 8 = ... → std ≈ 0.32
- A_1 = (0.0 − 0.5875) / 0.32 ≈ −1.84
- A_8 = (1.0 − 0.5875) / 0.32 ≈ +1.29

→ 优势值大致在 [−2, +2] 区间，对 PPO 裁剪友好。

#### 5.9.4 KL 惩罚量级

**题目**：SFT 模型对某 token 的概率为 0.5，新策略为 0.4，问 KL 散度与 β=0.1 时的损失贡献。

**解答**：
- 单 token KL：`KL(0.5 ‖ 0.4) = 0.5 · log(0.5/0.4) + 0.5 · log(0.5/0.6) ≈ 0.5 × 0.223 + 0.5 × (-0.182) ≈ 0.0205`
- 序列级（512 token）KL：–10.5
- 损失贡献：`β × 10.5 = 1.05` ——和 RM 单条奖励量级相当，KL 系数 0.1 已能强烈约束

### 5.10 面试题精选（25 选 12 高频）

#### 概念类

1. **RLHF 三阶段是什么？** → SFT → 训 RM（Bradley-Terry）→ PPO 优化（KL 约束）。
2. **为什么 PPO 需要四模型？** → Actor 训、Critic 训、RM 冻结打分、Reference 冻结算 KL。
3. **为什么必须有 KL 约束？** → RM 不完美，无约束会 reward hacking；KL 把策略拴在 SFT 附近。
4. **DPO 的核心推导在做什么？** → 对 KL 约束目标解析求解最优策略，反解 r，代入 Bradley-Terry 消去 Z(x)。
5. **DPO 相比 PPO 的优势？** → 只需 2 个模型（policy + reference）、无需 RM/采样、效果相当。
6. **GRPO 为什么能省 Critic？** → 用组内采样统计 (mean/std) 当优势基线代替 Critic 学到的价值。
7. **RLVR 是什么？为什么 R1 用？** → 可验证奖励 RL（规则自动判分），适合数学/代码任务，不可被 hack。
8. **GRPO 的三个已知问题？** → 长度偏差、零梯度组、熵崩溃。
9. **DAPO 的关键改动？** → 动态采样（过滤全对/全错组）+ clip-higher（裁剪上界 +40%）。
10. **GSPO 改了什么？** → token 级 IS 比改序列级 IS 比，对 MoE 训练尤其稳定。
11. **reward hacking 举例？** → 冗长谄媚文本刷分；模型"发现"RM 的偏见。
12. **RLAIF 是什么？** → 用 LLM 按原则生成偏好数据替代人工标注。

#### 工程类

13. **RLHF 工程上最大痛点？** → 显存（4 模型）+ 不稳定（PPO 超参敏感）+ 数据效率低。
14. **RM 训练为什么用 pairwise 而不是打分？** → pairwise 跨样本一致性好，Bradley-Terry 假设下与"潜在奖励"等价。
15. **DPO 的 β 怎么选？** → 任务越复杂/越偏离分布越小；典型 0.1–0.5。
16. **GRPO 的 G 大小怎么选？** → 越大越好（组内统计更稳定），但内存线性涨；典型 8–16。
17. **GRPO 与 DPO 能组合吗？** → 可以，常见做法：先用 DPO 冷启，再用 GRPO 在线训。
18. **推理模型训练的标准 pipeline？** → 长 CoT SFT 冷启 → GRPO + RLVR → DPO 精修。
19. **PRM 怎么训？** → 对每一步用蒙特卡洛估计"该步后能正确解题的概率"作为过程奖励。
20. **为什么 R1 不用 KL 约束？** → clip-higher + 组内机制已能控漂移；KL 反而抑制推理时的多样性。

#### 综合类（高阶）

21. **完整描述 InstructGPT 三阶段？** → （按 5.2 节三段讲）
22. **从 RLHF 到 GRPO 的演化逻辑？** → 4 模型 → 2 模型 → 1–2 模型 + 在线采样；显存与稳定性的持续 trade-off。
23. **什么是"第三条 scaling 路线"？** → RLVR / 推理时算力扩展（inference-time compute scaling）。
24. **Self-Evolving RL 的核心思想？** → 让 Agent 自造任务自训，配合课程学习保持"能力前沿"。
25. **如果让你设计对齐 pipeline，怎么选？** → 答：根据任务定：通用对话 SFT→DPO 即可；推理任务加 GRPO；能力超复杂上 PPO。

### 5.11 三句话总结与延伸阅读

**三句话总结**：
1. **RLHF 是把"人类偏好"灌进模型**——通过 SFT → RM → PPO 三阶段流水线实现，本质是用 RL 在 RM 这个不完美代理上做梯度。

### 5.12 解码策略（与 RL 训练密切相关的工程基础）

虽然解码属于推理侧，但 RL 训练阶段策略模型的"行为"也要靠解码采样来评估。本节把 6 种主流策略理清。

#### 5.12.1 五大策略对比

| 策略 | 公式 | 特点 | 适合 |
|---|---|---|---|
| **Greedy** | `argmax P(y_t\|y_<t)` | 确定性，可能死循环 | 评测基准 |
| **Beam Search** | top-B 路径展开 | 比贪心稳，O(B^d) | 翻译、摘要 |
| **Sampling** | 按 P 随机采样 | 多样性好 | 创作、对话 |
| **Top-k** | 只在 top-k 采样 | 截断长尾 | 平衡 |
| **Top-p (nucleus)** | 累积概率 ≥ p 的最小集合 | 自适应截断 | 通用首选 |
| **Temperature** | 调 logits /τ | τ 小于 1 更确定；τ 大于 1 更随机 | 全场景可调 |

#### 5.12.2 Temperature 公式

```
   P_τ(y_t = v) = exp(z_v / τ) / ∑_v' exp(z_v' / τ)
```

- τ → 0：趋向 argmax（贪心）
- τ = 1：原分布
- τ → ∞：趋向均匀分布

#### 5.12.3 推理 RL 中的解码

GRPO 训练时通常：
- 采样阶段：`temperature ∈ [0.6, 1.0]` + top-p=0.95
- 评测阶段：greedy / temperature=0
- 这种"训练时随机、评测时确定"的设置能避免策略过拟合到单一 token

### 5.13 Prompt Engineering 与思维链（推理 RL 的前置能力）

在 RL 训练推理模型前，先要理解模型已经具备的推理能力——这些是 GRPO 的起点。

#### 5.13.1 CoT（Chain of Thought）

- **Wei et al. 2022**：在 prompt 中加 "Let's think step by step" 让模型先写中间步骤再答；
- **关键发现**：模型规模 ≥ 100B 后，CoT 提升才显著（涌现现象）；
- **机制**：CoT 缓解了单步推理的容量瓶颈，把隐性多步推理显性化。

![Chain-of-Thought 随模型规模涌现：MultiArith / GSM8K 上的解出率](images/cot_scaling.png)

#### 5.13.2 ToT（Tree of Thoughts）

- **Yao et al. 2023**：CoT 的扩展——在每一步维护 B 个候选分支，用 LLM 自己评估 + 剪枝 + 回溯；
- 适合需要搜索/规划的任务（如 24 点、Game of 24）；
- 工程代价高，推理成本是 CoT 的数倍。

#### 5.13.3 ReAct（Reasoning + Acting）

- **Yao et al. 2023**：把推理与工具调用交替：
  ```
  Thought: 我需要查今天的天气
  Action: search("天气 北京")
  Observation: 25℃，晴
  Thought: 天气不错，可以出门
  Action: finish("建议外出")
  ```
- 这是 Agent 时代 CoT 的核心扩展（详见第 9 章）。

![Tree of Thoughts：CoT 的搜索树扩展](images/tot_tree_search.png)

#### 5.13.4 Self-Consistency（多采样投票）

- **Wang et al. 2023**：同一问题采样 K 个 CoT 回答，多数投票选最终答案；
- 经验值：K=5–40，提升数学推理 5–10 个百分点；
- 与 GRPO 思想一脉相承——组内统计提供更稳定信号。

### 5.14 后训练（Post-training）整体工程经验

#### 5.14.1 三种 SFT/RL 的常见组合

```
   路线 A（轻量）
   SFT 通用对话数据
       ↓
   DPO 通用偏好对齐
       ↓
   部署
   
   路线 B（推理专精）
   SFT 长 CoT 推理数据（冷启）
       ↓
   GRPO + RLVR 数学/代码规则奖励
       ↓
   DPO 精修（可选）
       ↓
   部署
   
   路线 C（顶级）
   SFT 通用对话
       ↓
   RM 训练（百万级偏好对）
       ↓
   PPO 多轮迭代
       ↓
   DPO 兜底
       ↓
   部署
```

#### 5.14.2 显存预算经验值（70B 模型）

| 阶段 | 模型数 | 显存（H100 80GB） |
|---|---|---|
| SFT | 1 + LoRA | 16GB |
| RM 训练 | 2（SFT + 标量头） | 32GB |
| PPO RLHF | 4 | 8 卡 H100 |
| DPO | 2 | 32GB |
| GRPO | 1 + reference | 32GB |

#### 5.14.3 工程监控指标（上线前必看）

- **奖励作弊率**：奖励均值/方差、长度相关性；
- **KL 漂移**：策略与 π_SFT 的平均 KL 应稳定在 0.01–0.1；
- **回答多样性**：n-gram 重复率、Self-BLEU；
- **能力回归**：MMLU / GSM8K / HumanEval 在每 100 step 跑一次；
- **推理任务专属**：Pass@K、Consistency@K、回答长度分布。

#### 5.14.4 训练失败常见原因

| 症状 | 根因 | 修复 |
|---|---|---|
| 训练初期 KL 飙升 | β 太小 | 加大 β（0.1→0.5） |
| RM 分持续走高但回答崩坏 | reward hacking | 加 KL、长度惩罚 |
| 回答长度单调下降 | GRPO 长度偏差 | 用 Dr.GRPO 序列级归一化 |
| Pass@1 降但 Pass@K 升 | 探索不足 | 加大 clip-higher、提高温度 |
| 训练崩盘 loss=NaN | 学习率过大 | 降 LR、增加 warmup |

### 5.15 三句话总结（本章）

1. **RLHF 用 RM 当代理做 RL**——SFT → RM（Bradley-Terry）→ PPO（KL 约束），三阶段奠定大模型对齐。
2. **DPO/GRPO 是 RLHF 的两次简化**——DPO 闭式损失去掉 RM（2 模型），GRPO 用组内统计去 Critic（推理任务首选）。
3. **2025 后训练前沿是 RLVR + 修 GRPO 偏差**——RLVR 用规则奖励避开 hack；DAPO/GSPO/GMPO 各自修三大问题，DeepSeek-R1 把范式推到极致。
