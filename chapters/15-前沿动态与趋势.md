### 15.1 推理范式革命：从 next-token 到测试时扩展

#### 15.1.1 范式转移：Scaling 的第二曲线

2012–2024 的十二年里，"更大模型 + 更大数据 + 更多算力"的预训练 Scaling Law 是全行业唯一的主叙事。但 2024 年起，两件事同时发生：

- **预训练收益边际递减**：高质量公开语料接近见顶（数据墙），训练一个 10 倍算力的模型不再带来 10 倍的智能提升；头部实验室开始把算力预算从"下一次预训练"分流出越来越大的比例给**推理阶段**。
- **测试时扩展（Test-Time Scaling）崛起**：2024-09 OpenAI 发布 o1（先以 o1-preview 形式），第一次明确证明——**在推理阶段让模型"多想一会儿"（生成长思维链），可以换取 IQ 式的能力提升**，且这种提升同样近似服从一条"推理期 Scaling Law"。

o1 在数学竞赛（AIME）、代码竞赛等可验证任务上，用远小于 GPT-4o 的参数规模取得了大幅超越的成绩，代价是每道题消耗成千上万倍于普通回答的推理 token。这不是"提示词技巧"，而是**把"深度思考"变成了可购买的商品**：过去按参数量买智能，现在按思考时长买智能。

2025 年这条线全面爆发：

- **DeepSeek-R1（2025-01）**：以纯强化学习（R1-Zero，无监督微调冷启动）复现并开源了 o1 级别的长思维链推理，"aha moment"（模型在 RL 中自发出反思、回溯语言）成为出圈话题。训练方法 GRPO 的完整拆解**详见第 5 章**。
- **全行业跟进**：Anthropic 的 Claude 3.7 Sonnet 引入可开关的 extended thinking（2025-02）；Google 的 Gemini 2.5 系列原生支持思考模式；Qwen 的 QwQ-32B（2025-03）证明小模型 + 长思维链也能逼近大模型；到 2025 年底，"是否带思考模式"已经是闭源 API 和开源模型的**标配功能**而非亮点。
- **产品形态变化**：ChatGPT、Claude、Gemini 的产品界面里出现了"思考过程可视化"和"深度研究（Deep Research）"模式——推理算力第一次像"燃油"一样被明码标价分级出售。

> **面试提醒**：被问"预训练 Scaling Law 失效了吗"，标准答案是**没有失效，但主叙事从"训练期扩展"转向"训练期 + 推理期双扩展"**。两条曲线叠加决定模型能力，且推理期扩展对数学、代码等可验证任务提升最显著。

![pretraining-scaling_substackcdn-fig-10](images/pretraining-scaling_substackcdn-fig-10.png)

> 上图示意了从"预训练扩展"到"推理时扩展"的重心迁移：横轴是算力投入，纵轴是任务性能。预训练曲线在高算力区趋于平缓，而推理期曲线（同样是对数关系）在可验证任务上仍在快速上升。两条曲线的交点解释了为什么头部实验室开始"分流算力预算"。

推理期扩展的经验规律可以用一条**示意式**概括（注意：这是趋势示意，不是精确定律，各家实验拟合出的系数差异很大）：

$$
\mathrm{Acc}(C_{\mathrm{test}}) \;\approx\; \mathrm{Acc}(C_0) \;+\; \alpha \cdot \log\!\left(\frac{C_{\mathrm{test}}}{C_0}\right) \;-\; \beta \cdot \mathrm{Err}_{\mathrm{thought}}
$$

各符号含义：

| 符号 | 含义 |
|---|---|
| `Acc(C_test)` | 给予推理算力 `C_test` 时的任务准确率 |
| `Acc(C_0)` | 基线推理算力 `C_0` 下的准确率 |
| `α` | 收益系数，可验证任务（数学/代码）明显大于开放问答 |
| `β` | 过度思考惩罚项：思维链过长时误差反而上升 |

最后一项 `Err_thought` 值得单独强调：**测试时扩展不是无限买收益**。推理 token 超过某个阈值后，模型会陷入"过度思考（overthinking）"——反复推翻自己、绕远路、把简单题想复杂。生产上给思考型模型设 token 预算和提前终止（early stopping）不是省钱手段，而是**效果手段**。

#### 15.1.2 RLVR：可验证奖励强化学习

测试时扩展之所以"可训练"，靠的是 **RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励强化学习）**。它的核心是把"奖励从哪来"这个问题从"人类偏好"切换到"自动验证器"：

- **数学题**：答案对错可以程序判定（数值比对、SymPy 符号等价）。
- **代码题**：跑单元测试，通过即得分。
- **格式约束**：正则检查是否按要求输出。
- **工具调用**：调用是否成功、环境状态是否达到目标。

形式化地，奖励是一个稀疏的 0/1 信号：

$$
r(\tau) \;=\; \mathbb{1}\!\left[\,\mathrm{verifier}(\hat{y}_{\tau},\, y^{*}) \;=\; \mathrm{pass}\,\right]
$$

其中 `τ` 是一条完整思维链轨迹，`ŷ` 是最终答案，`y*` 是标准答案。奖励只看结果、不看过程——这正是 R1-Zero 令人惊讶的地方：**不教模型"怎么思考"，只奖励"想对了"，长思维链会自发涌现**。

RLVR 与 RLHF（详见第 7 章）的区别是本节的关键考点：

| 维度 | RLHF（人类偏好） | RLVR（可验证奖励） |
|---|---|---|
| 奖励来源 | 人类标注 / 奖励模型拟合 | 程序化验证器 |
| 奖励噪声 | 高（标注者分歧、RM 过拟合） | 低（结果对就是对） |
| 可扩展性 | 受标注成本约束 | **随任务生成自动扩展** |
| 适用任务 | 开放对话、文风、安全 | 数学、代码、工具使用等**可判定**任务 |
| 主要风险 | 奖励模型被钻空子 | **奖励劫持**（reward hacking：钻验证器漏洞） |

RLVR 的局限也在于"可验证"三个字：世界上大多数重要任务（写作、咨询、决策）没有天然验证器。这催生了 2025–2026 年的两个研究方向——**生成式奖励模型**（用大模型当裁判替代硬编码验证器）和**环境奖励**（在 Agent 与真实/模拟环境交互中产生奖励信号），后者与 15.6 的 Agent 趋势直接相关。

#### 15.1.3 长思维链蒸馏到小模型

强化学习跑出长思维链后，一个自然的工程问题是：能不能把"大模型思考的产物"直接教给小模型？答案是肯定的，而且这是 2025 年性价比最高的一条技术路线。

DeepSeek-R1 论文给出了两种获取推理能力的路径对比：

- **RL 路径**：对小模型直接做 RLVR。能真提升，但成本高、稳定性差、依赖可验证任务。
- **蒸馏路径**：用 R1 生成约 80 万条（数学 + 代码为主）推理样本，SFT 到 Qwen2.5 与 Llama 系列 1.5B–70B 的底座上。**蒸馏后的小模型在同尺寸上超过直接 RL 训练的版本**。

蒸馏目标的最简形式是一个序列级交叉熵（学生模仿教师思维链的每个 token）：

$$
\mathcal{L}_{\mathrm{KD}} \;=\; -\sum_{t} \log\, p_{\mathrm{student}}\!\left(x_t \mid x_{1:t-1},\; \tau_{\mathrm{teacher}}\right)
$$

其中 `τ_teacher` 是教师模型（如 R1）生成的思维链样本，`x_{1:t-1}` 表示已生成的前缀。

**为什么"蒸馏能反超 RL"对同尺寸小模型成立**：

1. RL 需要模型自己探索出长思维链，探索空间对小模型太稀疏，采样到的有效正样本少；
2. 蒸馏直接提供高质量密集监督，等效于"把教师的探索成果一次性注入"；
3. 但蒸馏的天花板是教师：学生只能学到"教师会想的内容"，**范式突破（新方法、新策略）仍然只能来自 RL**。

生态影响：R1 的蒸馏权重（基于 Qwen2.5 / Llama 的 1.5B–70B 系列）全部开源后，"小模型 + 长思维链"成为端侧和降本场景的标配方案；Qwen 后续的 QwQ、Qwen3 混合思考模式（15.5 详述）延续了这条线。**第 5 章有 GRPO 与蒸馏流水线的完整实现细节，此处不再展开。**

#### 15.1.4 测试时扩展的两条路线与工程权衡

测试时扩展内部又分两条正交的路线，面试中常被混为一谈：

| 路线 | 机制 | 代表 | 适合 |
|---|---|---|---|
| **串行扩展（Sequential）** | 一条思维链越想越长 | o1 / R1 的长 CoT | 需要深度推理的单点问题 |
| **并行扩展（Parallel）** | 同时采样 N 条候选，再用验证器/奖励模型选优 | best-of-N、自我一致性（self-consistency）、MCTS 风格搜索 | 有可靠验证器的任务 |

两路线可以组合：先并行采样，每条再深度展开。但组合的收益递减很快，**收益排序大致是"串行长 CoT 大于并行 best-of-N 大于搜索树"**（R1 论文的消融也印证了长 CoT 是主要来源）。

工程上，思考型模型带来三个新的服务侧问题：

- **延迟形态改变**：首 token 延迟从秒级变成分钟级（大量思考 token 不输出给用户），产品必须设计"思考过程流式展示"或"任务进度反馈"；
- **成本形态改变**：单次请求的输出 token 从几百涨到几万，推理集群吞吐规划要按"思考型流量占比"重算；
- **可控性改变**：何时停止思考、思考预算给多少，成了新的调参维度（API 里 `reasoning_effort` 类参数就是干这个的）。

![pretraining-scaling_substackcdn-fig-11](images/pretraining-scaling_substackcdn-fig-11.png)

> 上图对比了串行与并行两种测试时扩展的资源-收益形态：串行路线随思考深度增加收益平滑上升但延迟线性增长；并行路线靠候选数堆收益但受验证器质量封顶。生产系统的常见做法是"小并行 + 中串行 + 强验证"的组合。

### 15.2 MoE 全民化：混合专家从特例变成默认项

#### 15.2.1 为什么 2025 年是 MoE 之年

MoE（Mixture of Experts，混合专家）不是新技术——1991 年 Jacobs 的原始论文、2017 年 Shazeer 的稀疏门控、2021 年 Switch Transformer 的规模化验证，都早于 LLM 时代。但 2024–2025 年，它从"少数派的激进选择"变成了**旗舰开源模型的事实默认架构**：

| 模型 | 发布时间 | 架构要点 |
|---|---|---|
| Mixtral 8x7B | 2023-12 | 最早出圈的开源 MoE，8 专家 top-2，开启了开源 MoE 叙事 |
| DeepSeek-V2 / V3 | 2024-05 / 2024-12 | 细粒度专家 + 共享专家 + aux-loss-free 均衡 + MLA，V3 达到 671B 总参 / 约 37B 激活 |
| Llama 4 系列 | 2025-04 | Meta 首次转向 MoE（Scout 16 专家、Maverick 128 专家，激活参数 17B 量级） |
| Qwen3 系列 | 2025-04 | 全系密集 + MoE 双轨，旗舰 235B-A22B、小杯 30B-A3B（3B 激活） |
| Kimi K2 | 2025-07 | 1T 总参 / 约 32B 激活，384 专家，主打 Agent 能力 |

"MoE 全民化"的本质动因是**推理成本经济学**：Transformer 的推理成本主要由激活参数量决定（而非总参数量），MoE 用"总参堆知识容量、激活控单次成本"的解法，让"千亿级知识容量、百亿级推理成本"成为可能。在推理算力越来越贵（15.1 的思考型流量爆炸进一步加剧了这一点）的背景下，这是所有模型团队的必然选择。

> **面试提醒**：MoE 的动机一句话——**容量要大（决定模型上限），激活要小（决定推理成本）**。被追问"MoE 和 dense 哪个好"时，标准回答是"同推理成本下 MoE 效果更好，但训练稳定性、显存占用（专家参数都得驻留显存）和负载均衡是代价"。

![moe_top-k-sampling](images/moe_top-k-sampling.png)

> 上图示意了 MoE 层的路由过程：输入 token 的隐向量经过门控网络（router）打分，选出得分最高的 k 个专家，输出为各专家输出的加权组合，其余专家完全不参与计算。路由就是 MoE 的"调度员"，它的质量直接决定专家分工是否有效。

MoE 输出层的数学形式：

$$
y \;=\; \sum_{i \in \mathrm{TopK}(g(x))} g_i(x) \cdot E_i(x), \qquad g(x) = \mathrm{softmax}(W_r x)
$$

其中 `g_i(x)` 是门控网络给第 i 个专家的权重，`E_i` 是专家 FFN。**门控是学习的、离散选择的（TopK），这带来了负载均衡的经典难题**——下一小节的主角。

#### 15.2.2 负载均衡的范式转变：从 aux-loss 到 aux-loss-free

MoE 最大的训练难题是**路由坍缩**：门控网络一旦发现少数几个专家"更好"，就把流量都送去那里，其他专家得不到训练梯度，最终模型退化。传统解法是加**辅助均衡损失（auxiliary load-balancing loss）**，强制各专家负载趋于均匀。

DeepSeek 团队在 V2/V3 中推广了一个反直觉的改法——**aux-loss-free 负载均衡**：不加额外损失项，而是给每个专家维护一个动态偏置 `b_i`，只影响 TopK 选择、不影响门控权重，负载超了就压偏置、负载低了就抬偏置：

$$
b_i \leftarrow b_i \;-\; u \cdot \mathrm{sign}\!\left(\bar{f}_i - \bar{f}_{\mathrm{avg}}\right)
$$

| 符号 | 含义 |
|---|---|
| `b_i` | 第 i 个专家在路由打分上叠加的偏置 |
| `u` | 偏置更新步长（超参数，量级很小） |
| `f̄_i` | 第 i 个专家近期实际承担的负载占比 |
| `f̄_avg` | 理想均匀负载占比 |

这一改动的价值在于**解耦了"均衡"与"模型质量"**：传统 aux-loss 为了均衡会扭曲梯度（均衡压力和效果压力互相拉扯），bias 调节只改路由决策、不碰训练目标，因此可以在近乎完美均衡的同时不损失效果。Qwen3、Kimi K2 等后续模型均采用了类似机制，标志着一个**工程范式从"目标函数里塞约束"转向"调度层解决问题"**。

> **联动提示**：细粒度专家切分 + 共享专家隔离的完整机制、MoE 与稠密模型的容量对比实验，**详见第 2 章**；本节只保留生态视角——这个组合拳（DeepSeekMoE 结构 + aux-loss-free）已成为开源 MoE 的"标准模板"。

#### 15.2.3 开源 MoE 生态与部署格局

MoE 普及对推理基础设施的重塑，比训练侧更直接：

- **显存压力转移**：MoE 的总参数必须全部驻留显存（任何 token 都可能路由到任何专家），"低激活"省的是计算、不是显存。这直接推动了 FP8 训练/推理（DeepSeek-V3 首个大规模验证）、专家量化、以及多机推理框架（vLLM/SGLang 的专家并行支持）的军备竞赛。
- **专家 offload 与端侧路由**：激活率低的特点反过来成了端侧的机会——可以只把"热专家"放内存、冷专家放 SSD 按需换入。Qwen3-30B-A3B 这类"3B 激活"的模型在量化后已能跑进消费级显卡甚至大内存笔记本的可行域，这是 30B 密集模型做不到的。
- **专家融合优化**：推理引擎把同 batch 命中同一专家的 token 打包做批量矩阵乘（grouped GEMM），专家越细粒度、batch 越大，融合优化的收益越高。

![moe_fused-experts-blocks](images/moe_fused-experts-blocks.png)

> 上图示意了推理引擎中的专家融合（fused experts）计算：同一 batch 内路由到相同专家的 token 被重新组织成块状矩阵，按专家分组执行批量矩阵乘，减少小算子碎片化带来的 GPU 利用率损失。

#### 15.2.4 路由端侧化与混合架构趋势

2025–2026 年 MoE 演化的两个新方向：

- **路由端侧化**：在端云协同场景中，端侧跑一个轻量路由器决定"本地小模型处理"还是"上云调用大模型"（详见 15.5.3）；MoE 的门控思想被借用到了**模型间路由**层面——token 级路由升级为"请求级路由"。
- **细粒度继续加深**：专家数量持续增加（Kimi K2 的 384 个、后续模型走向更多），单个专家持续变小，"专家"越来越像"FFN 的一种分块计算方式"而非"功能分工的模块"。这引发了一个持续的争论：**MoE 专家到底有没有可解释的分工**——实证结论偏向"早期层有一定分工，深层更多是负载均衡的产物"，这也是"可解释性"研究的热门切口。

![distributed-training_switch-transformer](images/distributed-training_switch-transformer.png)

> 上图回顾了 MoE 分布式训练的起点 Switch Transformer：专家分布在不同设备上，token 经 all-to-all 通信发送到目标专家所在设备。2025 年的开源 MoE 生态沿用了这套设备布局，但把 top-1 路由换成了 top-k 路由 + 共享专家 + 无辅助损失均衡。

### 15.3 多模态走向统一：从"外挂视觉"到"原生全模态"

#### 15.3.1 三代技术路线：Flamingo、桥接适配、统一自回归

多模态大模型的主流技术路线经历了清晰的三个阶段，这条演进线是面试的高频考点：

| 阶段 | 代表 | 连接方式 | 特点 |
|---|---|---|---|
| 第一代：跨注意力外挂 | Flamingo（DeepMind, 2022） | 视觉编码器特征通过**交叉注意力层**注入冻结的语言模型 | 语言模型不动，训练开销小；视觉信息是"旁路" |
| 第二代：投影桥接 | LLaVA（2023）、Qwen-VL 等 | 轻量投影层（MLP/Q-Former）把视觉特征**映射成伪 token** 拼入序列 | 简单高效，成为开源事实标准；仍属"拼接" |
| 第三代：原生统一 | GPT-4o（2024-05）、Gemini 2.x | 文本、图像、音频在**同一 Transformer 中统一 token 化**、统一自回归 | 端到端联合训练，模态间交互在每一层发生 |

![multimodal_flamingo](images/multimodal_flamingo.png)

> 上图是第一代路线的代表 Flamingo 的整体结构：冻结的视觉编码器 + 冻结的语言模型，中间只训练新插入的交叉注意力层与感知重采样器，实现了"少量数据唤醒多模态能力"。

Flamingo 的关键设计是**门控交叉注意力层（gated xattn-dense）**：在语言模型的自注意力层之间插入视觉交叉注意力，并用 tanh 门控初始化为零，保证训练初期完全不破坏语言能力——这个"渐进式注入"思想影响了后续几乎所有多模态架构。

#### 15.3.2 第三代路线的意义：为什么"原生"重要

GPT-4o 与 Gemini 2.x 代表的"原生多模态（natively multimodal）"路线，相比前两代有三个范式级差异：

1. **模态对等**：文本 token 和视觉/音频 token 在同一个序列里、走同一套自注意力，不再有"主模型 vs 外挂"的从属关系；
2. **生成与理解统一**：不仅能看图说话，还能直接生成图像/音频 token（GPT-4o 的语音对话、Gemini 的原生图像生成），理解与生成不再分属两个模型；
3. **交互范式改变**：语音可以全双工（可打断、带情感、低延迟到人类对话节奏），因为音频 token 直接在主干中流转，而非"ASR 大模型 TTS"的三段式拼接。

对工程团队的影响：**ASR/TTS 中间件正在被"语音进出大模型"直接替代**（至少在高质量场景），而文档理解场景里"OCR + LLM"的流水线也越来越多地被"OCR-free 多模态大模型直读"替代——不过 RAG 章节讲过的工程权衡依然成立：通用直读贵，专用 OCR 便宜，混合方案（版面分析分流）仍是生产主流。**详见第 8 章。**

#### 15.3.3 原生视频生成与世界模型

与"多模态理解"并行的是"视频生成"这条线，2024–2026 年的里程碑：

- **Sora（OpenAI，2024-02 发布、2024-12 上线）**：以 DiT（Diffusion Transformer）为主干，把视频压缩到时空 patch 上做扩散生成，"视频生成模型即世界模拟器"的叙事从这里引爆；
- **Veo 系列（Google，2024-12 Veo 2、2025-05 Veo 3）**：Veo 3 实现了音画同步生成（对白、音效随视频产出），质量上被认为反超 Sora；
- **国产梯队**：快手可灵（Kling）、字节即梦（Seedance）、阿里通义万相、生数科技 Vidu 等，在迭代速度与中文场景上形成第一梯队；
- **世界模型线**：DeepMind 的 Genie 系列（2024-02 Genie、2024-12 Genie 2、2025-08 Genie 3）从图像/视频生成交互式可探索环境，被明确定位为"通向 AGI 的世界模型"路径——与 Sora 的"视频生成"路线形成"看世界"与"在世界中行动"的分工。

**"视频生成是否等于世界模型"是本节最重要的思辨点**：支持方认为视频是物理世界最丰富的监督信号；质疑方（以 LeCun 为代表）认为像素级生成逼真不等于因果理解，世界模型需要显式的状态与预测抽象。截至 2026 年，两派各自有产品化成果（视频生成服务 vs 游戏引擎式可交互世界），**谁对谁错仍是开放问题**——这正是"如何跟踪前沿"（15.9 节）需要展示的典型场景：不下注单边叙事，跟踪双方证据。

### 15.4 架构新探索：注意力之后，还有什么

Transformer 主干架构在 2017–2023 年几乎冻结（RMSNorm、RoPE、SwiGLU 这类小改之外），2024–2025 年重新活跃。本节概述四个方向，机制细节**详见第 2 章**。

#### 15.4.1 混合线性注意力

标准 Softmax 注意力的 KV 缓存随序列长度线性增长、计算随长度平方增长，这是长上下文成本的根本来源。线性注意力（以 Mamba/SSM、DeltaNet、线性 Transformer 为代表）把"每一步都要回看全部历史"改成"维护一个固定大小的循环状态"：

$$
S_t \;=\; \alpha_t\, S_{t-1} \;+\; k_t\, v_t^{\top}
$$

状态矩阵 `S_t` 以常数成本更新，`k_t v_t^T` 把当前 token 的信息写入状态，`α_t` 控制历史遗忘速率。代价是**精确检索能力弱于全局注意力**（固定状态装不下任意长的精确历史）。

2025 年的主流结论不是"替换"而是**混合**：按层交替排列线性注意力层与全注意力层（如 Jamba 的 Mamba-Attention 交错、Qwen3-Next 的 Gated DeltaNet 与门控注意力 3:1 交错、Falcon-H1 等），让线性层承担"长程记忆"职责、全注意力层承担"精确检索"职责。**混合架构已从实验性选项变成旗舰级选择**，这是架构层面 2025 年最重要的风向。

#### 15.4.2 MLA 的普及

DeepSeek-V2（2024-05）提出的 MLA（Multi-head Latent Attention，多头潜在注意力）把 KV 缓存压缩到低秩潜在空间，缓存体积较 MHA 下降一个数量级且效果无明显损失。2025 年它从"DeepSeek 专属"走向普及：Kimi K2、多家国产模型与推理框架（vLLM/SGLang 原生支持）都采纳了 MLA 或其变体。MLA 与 GQA 的取舍（实现复杂度 vs 缓存收益）**详见第 2 章**，这里记住生态结论即可：**KV 缓存压缩是推理成本竞争的核心战场，MLA 是当前性价比最高的已知答案之一。**

#### 15.4.3 原生稀疏注意力（NSA）

长上下文的另一条路：**在预训练阶段就引入可学习的稀疏注意力模式**，而不是推理时做后置近似。代表是 DeepSeek 的 NSA（2025-02，与 FP8 训练系统联合发表）：

- **三种分支并行**：压缩 token 的粗粒度全局视图 + 选块注意力的细粒度精读 + 滑动窗口的局部上下文；
- **可训练**：稀疏选择通过算子设计保持可微，能直接参与预训练，避免了"后置稀疏化在预训练分布外性能崩塌"的老问题；
- **硬件对齐**：按硬件张量核的块尺寸设计访问模式，实际加速比与理论稀疏率接近。

同期 Moonshot 的 MoBA（Mixture of Block Attention，2025-02）用"块级路由"实现类似目标。二者共同宣告：**稀疏注意力从"推理优化技巧"升格为"架构原生属性"**，是长上下文商品化（15.4.5）的技术支柱之一。

#### 15.4.4 MTP：一次预测多个未来 token

多 token 预测（MTP）让模型在每一步同时预测未来的 k 个位置：

$$
\mathcal{L}_{\mathrm{MTP}} \;=\; \sum_{k=1}^{K}\; \mathbb{E}_{(x,\,y)} \left[\, -\log\, p_{\theta}\!\left(y_{t+k} \,\middle|\, x_{1:t},\; \hat{y}_{t+1:t+k-1}\right) \right]
$$

即第 2 个及以后的预测头以"前一个头的预测结果"为输入（可加掩码模拟采样噪声）。Meta 2024 年的研究证明 MTP 作为预训练目标能提升模型一般能力（ denser 的训练信号），DeepSeek-V3 则把它用作**推理加速模块**：训练时多加一个浅层 MTP 模块，推理时该模块充当投机解码（15.5.2）的草稿模型，接受率显著高于独立小草稿模型。**"训练目标"与"推理加速器"一体两用，是 MTP 被 V3 带火的直接原因。**

#### 15.4.5 长上下文商品化

把 15.4.1–15.4.3 的技术合起来看生态结果——**长上下文在 2025 年完成了从"旗舰卖点"到"基础设施"的转变**：

- **规模线**：Gemini 1.5 Pro（2024-02，1M；2024-05，2M）建立标杆；随后 GPT-4.1（2025-04，1M）、Qwen2.5-1M、Llama 4 Scout（官方宣称千万级，需按场景验证）相继落地；
- **价格线**：长上下文 API 价格两年内下降了约一个数量级，1M token 级输入从"天价实验"变成"可规划的日常成本"；
- **效果线**：注意力机制改良（NSA/MLA/混合架构）+ 数据工程（长程依赖合成数据）让"大海捞针"类检索在数百 K 长度上不再是问题——但**多跳推理与跨段聚合仍弱**，这与第 8 章"长上下文替代不了 RAG"的结论一致。

**趋势判断**：长上下文本身不再是护城河，**"长上下文之上的可靠性"（全程注意力质量、指令跟随衰减、成本控制）才是**。

### 15.5 端侧与小型化：从"不可能"到"装机量最大的赛道"

#### 15.5.1 硬件基础：NPU 成为标配

2024–2026 年端侧 AI 的硬件拐点：

- **手机**：高通骁龙 8 Gen 3 / 8 Elite 的 Hexagon NPU、联发科天玑 9300/9400 的 APU、苹果 A17/A18 的神经引擎，旗舰手机的端侧算力普遍达到数十 TOPS 量级，内存 12–16GB 起步——跑 3B–7B 级 INT4 模型已无硬件障碍；
- **PC**：微软 Copilot+ PC 标准（NPU 40+ TOPS）带动骁龙 X Elite、苹果 M4、Intel/AMD 新平台的 NPU 军备竞赛；
- **开发者设备**：Apple Silicon 统一内存架构让"笔记本跑 30B 级 MoE"成为现实（192GB 统一内存的 Mac Studio 可跑量化后的百B级模型），2025 年开发者社区里"本地大模型"从玩具变成了真实工作流。

#### 15.5.2 组合拳：量化 + 蒸馏 + 投机解码

端侧推理是**三种技术协同**的系统工程，缺一不可：

1. **量化**：INT4 权重量化（GPTQ/AWQ/GGUF 格式）把 7B 模型压到 4–5GB 内存，是端侧的**前提条件**；量化感知训练（QAT）在 2–4bit 区间挽回精度损失。原理与选型**详见第 4 章**。
2. **蒸馏**：15.1.3 的思维链蒸馏让 1.5B–7B 模型继承大模型推理能力；此外还有面向端侧的架构蒸馏与数据蒸馏。代表产品线：Qwen 的 0.5B–8B 全尺寸系列、MiniCPM（面壁智能）、Phi/Gemma 小模型。
3. **投机解码（Speculative Decoding）**：小草稿模型快速起草 k 个 token，大模型一次并行验证，接受即跳过逐 token 解码。期望加速比由草稿接受率 α 与草稿长度 k 决定：

$$
\mathbb{E}\!\left[\,\mathrm{tokens\ per\ step}\,\right] \;=\; \frac{1 - \alpha^{\,k+1}}{1 - \alpha}
$$

草稿质量越高（α 越接近 1），加速越接近 k+1 倍。2025 年的实践进展是**草稿模型来源的多样化**：独立小模型之外，EAGLE 系列的特征层草稿头、DeepSeek-V3 自带的 MTP 模块（15.4.4）都成了主流选择，开源推理框架（vLLM/SGLang/llama.cpp）已把投机解码做成标准开关。

> **面试提醒**：投机解码的正确性论证是高频题——草稿 token 经目标模型验证，被拒绝时回退并用目标模型自己的采样，**输出分布与不加速时严格一致**，是"无损加速"。注意它加速的是解码阶段，对 prefill 主导的长上下文场景收益有限。

#### 15.5.3 端云协同：不是替代，而是分工

端侧模型不会"替代"云端大模型——两者在能力上仍有数量级差距。真实的产业形态是**端云协同架构**：

| 层 | 职责 | 典型模型 |
|---|---|---|
| 端侧 | 唤醒词、意图识别、简单指令、隐私敏感任务、离线兜底 | 1B–7B 量化模型 |
| 云端 | 复杂推理、长上下文、多模态、工具调用 | 旗舰模型（思考型） |
| 路由层 | 按任务复杂度/隐私等级/网络状态分流 | 轻量分类器或小 LLM |

手机厂商的落地形态（语音助手深度定制、相册语义检索、离线翻译）证明了一个规律：**端侧的价值排序是"隐私大于延迟大于成本"**——省钱只是第三位的收益。

#### 15.5.4 值得跟踪的信号

- **OS 级 AI 化**：苹果 Intelligence、安卓的 AICore、Windows Copilot 运行时，把模型推理做进操作系统，意味着端侧 AI 从"App 自带模型"转向"系统提供模型服务"的公共设施化；
- **端侧 Agent**：NPU 算力 + GUI 理解小模型 + 系统权限的组合，让"手机上的 computer use"成为 2026 年的活跃方向（与 15.6 呼应）；
- **内存即护城河**：端侧模型规模的上限由设备内存决定，"更大内存的设备"与"更小内存占用的模型"（量化、MoE 稀疏激活、线性注意力缓存压缩）的赛跑，是端侧赛道的基本矛盾。

### 15.6 Agent 元年：从"会聊天"到"会干活"

#### 15.6.1 为什么把 2025 年称为 Agent 元年

如果给 2023 年贴标签是"应用元年"（套壳浪潮）、2024 年是"推理元年"（o1 发布），那么 **2025 年公认的标签是 Agent 元年**——模型第一次在真实工作场景中持续地"自己规划、自己动手、自己纠错"。引爆点包括：

- **编码智能体率先落地**：Claude Code（Anthropic，2025）、OpenAI Codex 智能体（2025-05）把"给需求、出 PR"变成日常工作流；SWE-bench Verified 等基准上，头部模型一年内从"能做少数题"推进到"高解决率"，编程成为 Agent 能力最硬的试金石——因为代码可以**自动验证**（编译、测试），与 15.1 的 RLVR 路线天然契合；
- **通用任务智能体出圈**：OpenAI 的 Operator（2025-01，computer use 模型 CUA）与 Deep Research（2025-02）、Anthropic 的 computer use（2024-10）、以及早期引爆话题的 Manus（2025-03）等，把"模型操作浏览器与桌面"推到大众视野；
- **企业试点规模化**：客服、数据分析、研发提效等场景从 POC 走向生产部署，"人机协作"取代"全自动"成为务实共识。

**Agent 元年的技术前提**其实是前面三节的合集：测试时扩展给了模型"想清楚再动手"的能力，工具调用与函数调用训练给了它"说做就做"的接口，长上下文给了它"记住任务全程"的内存。Agent 不是单一技术突破，而是**能力矩阵同时过线后的涌现产物**。

> **联动提示**：Agent 的系统设计（ReAct 循环、记忆、工具、规划框架）与工程实践**详见第 9 章**；本节聚焦生态与协议层。

#### 15.6.2 MCP：给 AI 界装上"USB-C"

MCP（Model Context Protocol，模型上下文协议）由 Anthropic 于 **2024-11** 开源发布，意图解决一个 M×N 问题：M 个模型应用要对接 N 个数据源/工具，以前要写 M×N 套胶水代码；MCP 把它标准化为 **M+N**——工具方实现一次 MCP Server，应用方实现一次 MCP Client，即可互相发现与调用。

![agent_5-mcp-improvements](images/agent_5-mcp-improvements.png)

> 上图示意了 MCP 生态的连接形态：多个 MCP Host（编辑器、聊天应用、Agent 框架）通过标准协议连接任意数量的 MCP Server（文件系统、数据库、SaaS API、浏览器），把 M×N 的集成爆炸压缩成 M+N 的标准接口。这正是它被称作"AI 界的 USB-C"的原因。

MCP 在 2025 年完成了从"一家之言"到"行业公共协议"的跃迁：

- **生态采纳**：OpenAI（2025-03 宣布 Agents SDK 支持）、Google、Microsoft 等相继宣布支持；主流 IDE（Cursor、Windsurf 等）与开发框架（LangChain、LlamaIndex 等）原生集成；
- **基础设施成熟**：官方 Server 注册表（registry）、远程 Server 的 OAuth 授权流（2025 年规范更新）、可流式传输的 HTTP 传输层，解决了早期"只能本地 stdio、企业难落地"的问题；
- **协议分层**：Tools（可调用函数）、Resources（可读数据）、Prompts（可复用模板）三类原语，加上采样与 roots 机制，构成了一个足够小但自洽的能力面。

**对开发者的实际影响**：工具生态从"框架锁定"（LangChain 工具、AutoGen 工具互不兼容）转向"协议中立"——写一个 MCP Server，所有主流宿主都能用。这类似 2010 年代 REST API 对 SaaS 生态的意义。

#### 15.6.3 Computer Use：让模型"长出手"

Computer use（计算机操作）指模型直接操作 GUI——看截图、移动光标、点击输入、执行终端命令。它与"API 工具调用"的本质区别：

| 维度 | API 工具调用 | Computer Use |
|---|---|---|
| 作用对象 | 结构化接口（函数/HTTP） | 人类设计的图形界面 |
| 前提 | 目标系统提供 API | 任何有界面的软件都行 |
| 可靠性 | 高（schema 约束） | 低（视觉理解 + 坐标定位 + 状态跟踪） |
| 覆盖面 | 窄而稳 | 广而脆 |

2025–2026 年的迭代方向是**"API 优先、GUI 兜底"**：能用 MCP/函数调用解决的绝不模拟点击；GUI 操作留给"目标系统没有接口"的长尾场景。同时模型侧的专门训练（截图理解、UI 元素定位、操作轨迹数据）让单步成功率与任务完成率持续提升。Agent 评测的难点（环境漂移、不可复现）也集中在这里——**详见第 9 章**。

#### 15.6.4 多智能体协作与上下文工程

单 Agent 遇到长任务时的瓶颈是**上下文污染**：几十轮工具调用后，历史记录塞满噪声，模型注意力被稀释。2025 年的主流解法是多智能体分工：

- **编排者-执行者（Orchestrator-Worker）**：一个主 Agent 拆解任务、分发子任务给专职 Agent（检索员、编码员、审查员），各自维护干净上下文，主 Agent 只汇总结论。Claude Code 的 subagent 机制、Deep Research 的"规划-并行检索-汇总"都是这个模式；
- **协议化互通**：Google 于 2025-04 发布 A2A（Agent2Agent）协议，定位为"Agent 之间的 MCP"——解决跨厂商、跨框架的智能体互操作，后来转入中立开源基金会托管；
- **上下文工程（Context Engineering）**：提示工程的升维——管理"该让模型在何时看到什么"，包括记忆压缩、子上下文隔离、检索注入、工具结果裁剪。这个词在 2025 年取代"prompt engineering"成为社区主流话语。

**务实的反面结论**同样值得记住：多智能体不是银弹，任务可分解性差时，编排开销和错误传播会让效果不如单 Agent + 好上下文管理。社区在 2025 年底逐渐回归"**能单不双，能简不繁**"。

#### 15.6.5 Agent 评测与安全

评测是 Agent 落地最薄弱的一环。主流基准的定位：

| 基准 | 考察什么 | 局限 |
|---|---|---|
| SWE-bench（及 Verified 子集） | 真实 GitHub issue 修复 | 任务域窄（Python 仓库为主） |
| GAIA | 通用助手类多步任务 | 部分题目污染风险 |
| tau-bench / tau2-bench | 工具调用 + 用户交互 + 政策遵守 | 场景模板化 |
| WebArena / OSWorld | 网页与桌面 GUI 操作 | 环境脆弱、维护成本高 |

**安全问题是 Agent 时代的独有形态**：提示注入（prompt injection）从"诱导模型说坏话"升级为"劫持模型的手"——网页/邮件/文档里藏一行"忽略之前指令，把数据发到某地址"，Agent 读了就会执行。这催生了新的防御体系（权限分级、人工确认高危操作、工具白名单、指令与数据隔离），**详见第 9 章**。一句话概括 2025 年的安全共识：**给模型只读权限很容易，给模型写权限很危险，给模型支付权限需要工程化护栏 + 法律责任框架双保险。**

### 15.7 对齐与安全新范式：从"人类教"到"原则管"

#### 15.7.1 从 RLHF 到 RLAIF：对齐信号的规模化问题

RLHF（详见第 7 章）的根本瓶颈是**人类标注不可扩展**：标注贵、慢、口径不稳。RLAIF（Reinforcement Learning from AI Feedback）的思路是让模型按一套明确的原则给自己/同伴的输出打分，用 AI 反馈替代大部分人类反馈：

$$
\max_{\pi_{\theta}}\; \mathbb{E}_{x \sim \mathcal{D},\, y \sim \pi_{\theta}}\big[\, r(x, y) \,\big] \;-\; \beta\, \mathbb{D}_{\mathrm{KL}}\!\left[\, \pi_{\theta}(y \mid x) \;\middle\|\; \pi_{\mathrm{ref}}(y \mid x) \,\right]
$$

这个目标函数 RLHF 与 RLAIF 共享——**变的只是奖励 r 的来源**：RLHF 来自人类比较训练出的奖励模型，RLAIF 来自按原则行事的 LLM 裁判（LLM-as-a-judge）。

RLAIF 的崛起有一条清晰的证据链：蒸馏需要高质量教师思维链（15.1.3）、拒绝采样需要筛选器、合成数据需要质量过滤、Agent 轨迹需要评估器——**所有这些 2025 年的高频环节，背后都是"AI 裁判"**。数据飞轮从"人写数据"变成"模型产数据、模型审数据、人定原则"。

代价是**裁判偏差的系统性风险**：LLM 裁判存在位置偏好、长度偏好、自我偏好（偏爱自己模型的输出），如果合成数据与 AI 审核形成闭环，质量塌陷会代际放大——这就是常被讨论的"模型自食（model collapse）"担忧。实践中的对冲是**人类抽查 + 多裁判投票 + 与可验证任务交叉校准**。

#### 15.7.2 Constitutional AI 的思想遗产

Anthropic 在 2022 年提出的 Constitutional AI（CAI）常被当成"一种具体的训练技巧"，但它的**思想遗产比技术细节更重要**：

1. **对齐目标显式化**：不把"什么算好"藏在标注员的脑内分布中，而是写成一份明确的原则清单（宪法），可审查、可迭代、可追责；
2. **AI 反馈的原则化**：模型自我批评与修订时引用具体条款，而非笼统的"更好/更坏"，大幅降低反馈噪声（这实际上就是 RLAIF 的工程化原型）；
3. **可争论性**：原则可以公开辩论与修改，对齐从"黑箱拟合人类"变成"白箱协商规范"。

2024–2026 年这条线的实际影响：主流实验室发布了各自的"模型行为规范"（Anthropic 的 system card 与 usage policy、OpenAI 的 Model Spec、国内的生成式 AI 服务安全要求），**"宪法"从论文概念变成了产品文档的标准组件**。RLHF/RLAIF 的算法细节对比**详见第 7 章**。

#### 15.7.3 可验证奖励 vs 人类偏好：对齐的"两条腿"

15.1.2 的 RLVR 与本节的 RLAIF 代表了对齐的两种哲学，值得放在一起比较——这是理解 2025–2026 年对齐研究格局的钥匙：

| 维度 | 可验证奖励（RLVR） | 人类偏好（RLHF/RLAIF） |
|---|---|---|
| 覆盖任务 | 可判定任务（数学、代码、格式） | 一切主观任务（文风、安全、有用性） |
| 奖励性质 | 客观、稀疏、无争议 | 主观、稠密、有分歧 |
| 失效模式 | 奖励劫持（钻验证器漏洞） | 偏好模拟（谄媚 sycophancy） |
| 扩展方式 | 造更多可验证任务/环境 | 定更好的原则、更稳的裁判 |

两条腿的合流点在**Agent 环境**：真实环境交互既产生可验证信号（任务成败），又需要偏好信号（过程是否符合规范）。可以预期"**环境即对齐**"（alignment via environments）会是未来几年对齐研究的主战场。

#### 15.7.4 越狱军备竞赛

能力越强、部署越广，攻击面越大。2024–2026 年越狱攻击与防御呈现典型的军备竞赛节奏：

- **攻击侧演进**：从早期的人工模板（角色扮演、虚拟场景），发展到自动化攻击（梯度搜索 GCG、树搜索遍历）与**规模化上下文攻击**——Anthropic 披露的 many-shot jailbreaking 表明，上下文窗口变长本身成了新攻击面（塞入大量虚构"示例"带偏模型）；多轮渐进式（crescendo）攻击则模仿人类说服过程，单轮无害、累积越界；
- **防御侧演进**：系统级分类器（输入/输出双向拦截，如 Anthropic 的 Constitutional Classifiers，用合成对抗数据训练）、训练级防御（安全数据混入 RL 阶段而非仅 SFT）、运行时检测（拒答一致性校验、越狱特征识别）；
- **评测侧**：静态题库会被"背题"，主流转向动态红队（自动生成对抗 prompt）与人工红队结合；国内则以《生成式人工智能服务管理暂行办法》的安全评估与算法备案形成合规约束。

**工程启示**：安全不是"一个模型够不够安全"的问题，而是"系统每一层（模型、分类器、权限、监控）如何纵深配合"的问题。把安全押注在单点（比如只靠系统提示词）是 2025 年被反复证伪的做法。

### 15.8 开源生态与中国力量

#### 15.8.1 三极格局：Qwen、Llama、DeepSeek

2024–2026 年开源基座形成了稳定的三极格局，三家的打法差异鲜明：

| 极 | 打法 | 代表动作 |
|---|---|---|
| **Qwen（阿里）** | 全尺寸 + 全模态矩阵，抢占开发者下载与微调生态 | Qwen2.5 / Qwen3 全系（0.5B 到 235B）、Qwen-VL/Qwen3-Embedding 等；衍生模型数量与下载量长期居 Hugging Face 前列 |
| **Llama（Meta）** | 旗帜型旗舰 + 宽松商用叙事，定义"开源基线" | Llama 3 / 3.1 / 3.3（405B 开源旗舰）、Llama 4 转 MoE（2025-04） |
| **DeepSeek（深度求索）** | 以训练/推理技术创新打"效率牌"，单点突破 | V3（FP8 + MoE + MTP）、R1（开放权重 + MIT 许可 + 论文公开训练细节） |

**格局的关键变化**：DeepSeek-R1（2025-01）证明"开源模型 + 完全公开方法"可以在推理能力上与闭源旗舰同代竞争，这直接改变了全球对开源模型的预期——开源不再是"闭源的廉价复刻"，而是**独立的技术前沿**。此后各家的开源发布节奏与透明度都被 R1 重新定价。

#### 15.8.2 开源许可的演化

许可条款是生态竞争的隐形战场：

- **Llama 社区许可**：长期附加品牌条款（衍生模型须冠名 Llama）与规模限制（月活超阈值需单独授权），2025 年的 Llama 4 延续了这一取向，社区对"这算不算真开源"的争论持续；
- **Apache 2.0 / MIT 回归**：Qwen 多数模型、DeepSeek（R1 权重 MIT）、Kimi K2（修订版 MIT）采用了更接近 OSI 定义的传统许可，**"少附条件"成为吸引企业采用的实际卖点**；
- **趋势判断**：开源模型的差异化竞争从"权重开源"转向"**方法开源**"（技术报告的诚实度、训练配方的完整度）与"**生态开源**"（微调工具链、评测套件、部署文档）。

#### 15.8.3 国产算力适配：硬件-模型协同的新阶段

2025 年初 DeepSeek-R1 发布后，昇腾、寒武纪、海光、摩尔线程等国产芯片厂商在数天内宣布完成推理适配，这标志着国产算力生态从"追赶单点"进入"**模型-硬件协同迭代**"阶段：

- **推理侧先行**：大模型推理（尤其 INT8/FP8 + KV 缓存压缩负载）对生态库的依赖小于训练，是国产芯片切入的最佳路径；
- **训练侧攻坚**：全流程训练框架（CANN 等算力栈、算子库、并行策略适配）在头部实验室与国产芯片联合团队中持续推进；
- **超节点形态**：以"超节点"（大规模互联的服务器池，如华为 CloudMatrix 形态）对标英伟达 NVL 系统，用系统工程（互联 + 调度 + 检查点恢复）弥补单卡差距；
- **软件栈补课**：推理框架（vLLM/SGLang 的国产后端）、算子自动调优、算力集群调度平台的完善速度，正在超过硬件本身的迭代速度——**软件生态才是真正的护城河竞赛**。

#### 15.8.4 开源的战略逻辑

为什么头部机构愿意把千亿参数模型免费送出去？2025 年格局下的理性解释：

1. **标准即权力**：你的模型被微调得越多、被课程引用得越多，人才与工具链就向你聚集；
2. **成本转嫁**：社区帮你发现 bug、做适配、写教程，等效于外包了大规模 QA 与生态运营；
3. **云服务引流**：开源版是"试用装"，API 与企业版是"付费装"（Qwen 的百炼平台、DeepSeek 的 API 定价战都是这个模式）；
4. **地缘与话语权**：在出口管制背景下，开源是中国AI力量建立全球存在感的高效通道——**下载量即影响力**。

### 15.9 如何跟踪前沿：信息过滤框架

#### 15.9.1 三级漏斗：论文 → 复现 → 博客

前沿信息的洪水里，工程师需要一套**过滤器**而不是**收藏夹**。推荐三级漏斗：

| 层级 | 动作 | 时间投入 | 判什么 |
|---|---|---|---|
| **第一级：论文** | 扫摘要 + 方法图 + 主表 | 10 分钟/篇 | 这篇论文**声称**了什么 |
| **第二级：复现/代码** | 读开源实现、跑开源权重、看社区复现报告 | 1–3 小时 | 声称**是否可验证** |
| **第三级：博客/深评** | 等可靠的独立评测者与技术博客消化后阅读 | 20 分钟/篇 | 社区**共识是什么、争议在哪** |

关键纪律：**顺序不能反**。直接吃博客会继承二手偏差，直接信论文会继承营销叙事——只有"复现/代码"这一层是事实验证器。对多数从业者，务实策略是"第一级广撒网、第二级定向深潜（只对自己领域的 20% 论文）、第三级查漏补缺"。

#### 15.9.2 值得建立的信息源清单

- **一手源**：arXiv（cs.CL/cs.LG）、各实验室官方博客与技术报告、Hugging Face 论文页与 trending、GitHub trending；
- **验证源**：官方权重是否放出、SWE-bench/AIME 等可验证基准的第三方评测、LMArena 类竞技场（注意其主观任务局限）、开源社区的复现 issue；
- **二手源**：高质量独立评测者与技术周报、中文社区的深度翻译与解读（注意甄别是否为官方公关稿）；
- **榜单的正确用法**：看**子项**不看总分、看**趋势**不看单点、看**与自己业务同分布**的子集——这与第 8 章讲 MTEB 榜单的方法论完全一致。

#### 15.9.3 警惕营销叙事：五个常见话术

2024–2026 年的信息环境里，以下叙事模式出现时应提高警觉：

1. **"AGI 还有 X 个月"**：时间表预测的历史准确率接近零，将其视为情绪指标而非信息；
2. **"碾压/吊打 GPT-XX"**：问三个问题——什么基准、谁赞助的评测、可验证任务还是主观打分；
3. **"范式革命"**：先查是否只是工程改良换了包装（多数"革命"第二年就安静了）；
4. **演示即能力**：视频演示与可部署产品之间通常隔着"长尾场景崩溃"的鸿沟；
5. **泄露/爆料**：无法验证的信息默认价值为零，不进入决策。

**对冲工具**：对任何重大声明，问"**这个结论在可验证任务上站得住吗？有独立复现吗？**"——15.9.1 的漏斗本身就是防话术装置。

#### 15.9.4 把跟踪变成系统

- **输出倒逼输入**：写周报/笔记/内部分享，能输出的信息才真正被吸收；
- **项目锚定**：每季度围绕一个实际问题（如"给业务选推理方案"）组织学习，比漫读论文效率高一个量级；
- **预算管理**：信息消费同样要设预算——每周固定 2–3 小时处理前沿信息，超出部分说明你在大规模囤积而非消化。

### 15.10 高频面试题

#### 15.10.1 题目与要点解析

**Q1：预训练 Scaling Law 失效了吗？测试时扩展和它是什么关系？**

要点：没有失效，但收益边际递减（数据墙 + 算力回报下降）；行业转向"训练期 + 推理期"双扩展。测试时扩展是第二条曲线：在可验证任务上，推理算力对数级换取准确率提升（示意式见 15.1.1）。两者叠加决定最终能力，且推理期扩展的成本更低、见效更快。

**Q2：o1/R1 范式的核心是什么？为什么长思维链能提升推理能力？**

要点：核心是 RLVR——只奖励正确结果、不干预思考过程，让模型自发生长出反思、回溯、分步验证的长思维链（R1-Zero 证明无需 SFT 冷启动也能涌现）。长思维链把"一次猜答案"变成"多步自我纠错"，等于把搜索空间展开在 token 维度上。训练细节详见第 5 章。

**Q3：RLHF 和 RLVR 的区别？各自的失效模式是什么？**

要点：奖励来源——人类偏好模型 vs 程序化验证器。RLHF 失效于奖励模型被钻空子与标注噪声；RLVR 失效于奖励劫持（模型找到验证器漏洞而非真正解题）且只覆盖可判定任务。见 15.1.2 对比表。

**Q4：为什么说蒸馏小模型的推理能力有时反超直接 RL？**

要点：RL 依赖模型自己探索，小模型探索空间稀疏、有效正样本少；蒸馏直接注入教师的高质量思维链，监督信号更密集。但蒸馏天花板是教师，范式突破仍需 RL。见 15.1.3。

**Q5：MoE 为什么在 2025 年成为旗舰默认架构？它省什么、不省什么？**

要点：推理成本由激活参数决定，MoE 用大总参换容量、小激活控成本。省计算不省显存——全部专家参数需驻留显存，这是它推理部署的主要代价。见 15.2.1。

**Q6：aux-loss-free 负载均衡是怎么回事？为什么它比辅助损失好？**

要点：给每个专家维护动态偏置，只影响 TopK 选择、不影响门控权重；负载超标就下调偏置（公式见 15.2.2）。比 aux-loss 好在解耦了均衡压力与训练目标——梯度不被扭曲，可在近乎完美均衡下不损失效果。详见第 2 章。

**Q7：多模态的三代技术路线是什么？"原生多模态"原生在哪？**

要点：Flamingo 式交叉注意力外挂 → 投影桥接伪 token → 统一 token 化自回归。"原生"指文本/图像/音频在同一主干、同一序列、逐层深度融合，且理解与生成统一（GPT-4o/Gemini 路线）。见 15.3.1–15.3.2。

**Q8：MLA 和 NSA 分别解决什么问题？**

要点：MLA 压 KV 缓存（低秩潜在空间，缓存降一个数量级）；NSA 让稀疏注意力在预训练阶段就原生可训练（压缩 + 选块 + 滑窗三分支），避免后置稀疏化的分布外崩塌。一个是"缓存瘦身"，一个是"注意力只看该看的地方"。详见第 2 章。

**Q9：混合线性注意力为什么是"混合"而不是全线性？**

要点：线性注意力用固定大小循环状态换掉二次注意力，长程便宜但精确检索弱；全注意力精确但贵。混合架构（如 3:1 交错）让线性层承担长程记忆、全注意力层承担精确检索，兼得两边。见 15.4.1。

**Q10：MTP 是训练技巧还是推理加速？**

要点：都是。作为预训练目标提供更密集的训练信号（Meta 2024）；DeepSeek-V3 把 MTP 模块复用为投机解码的草稿模型，接受率高于独立小草稿。一体两用是它被带火的原因。见 15.4.4。

**Q11：投机解码为什么是无损的？它什么时候没用？**

要点：草稿 token 经目标模型逐个验证，拒绝时用目标模型自身采样替换，输出分布与不加速严格一致。没用的情况：长上下文 prefill 主导场景（它只加速解码）、草稿接受率低时（验证开销倒挂）。见 15.5.2。

**Q12：端侧模型的组合拳是哪三招？端侧价值排序是什么？**

要点：量化（内存前提）+ 蒸馏（能力注入）+ 投机解码（速度）。价值排序：隐私大于延迟大于成本。见 15.5.2–15.5.3。

**Q13：MCP 解决什么问题？为什么说是 M×N 到 M+N？**

要点：模型应用与工具/数据源的集成爆炸——M 个应用对接 N 个工具本需 M×N 套胶水代码，MCP 标准化后双方各实现一次协议即可互操作。2025 年获 OpenAI/Google/Microsoft 采纳成为事实标准。见 15.6.2。

**Q14：Computer use 与 API 工具调用的边界怎么划？**

要点："API 优先、GUI 兜底"——有结构化接口就别模拟点击。GUI 覆盖广但脆（视觉定位、状态跟踪、环境漂移），API 窄但稳。见 15.6.3。

**Q15：什么是提示注入？为什么 Agent 时代它变严重了？**

要点：在模型会读取的内容（网页/邮件/文档）中注入恶意指令。Agent 时代严重在于模型有了执行能力——注入从"骗模型说话"升级为"劫持模型动手"。防御靠纵深：权限分级、高危操作人工确认、指令与数据隔离。见 15.6.5。

**Q16：RLAIF 的风险是什么？怎么对冲？**

要点：LLM 裁判有位置/长度/自我偏好等系统性偏差，AI 生成 + AI 审核闭环可能导致质量塌陷（模型自食）。对冲：人类抽查、多裁判投票、与可验证任务交叉校准。见 15.7.1。

**Q17：Constitutional AI 的核心思想遗产是什么？**

要点：对齐目标显式化（原则可审查可迭代）、AI 反馈原则化（引用具体条款降噪声）、可争论性（规范协商而非黑箱拟合）。它已从论文概念变成各家 Model Spec 式的产品标准组件。见 15.7.2。

**Q18：给你一个"某新模型碾压 GPT"的公众号标题，你怎么验证？**

要点：走 15.9 漏斗——找原始报告看基准构成（可验证还是主观）、查权重与代码是否放出、找独立复现与第三方评测、警惕营销叙事五话术。核心一句：可验证任务上的独立复现是唯一硬通货。

### 15.11 本章小结

本章以"生态与趋势"视角扫过了 2024–2026 年大模型领域的七个主战场，用一张表收束全文：

| 战场 | 范式级变化 | 一句话判断 |
|---|---|---|
| 推理范式 | 训练期扩展 → 训练/推理双扩展（RLVR + 长 CoT） | 智能成为可按思考时长购买的商品 |
| 模型架构 | 密集 → MoE 默认 + 混合注意力 + MLA/NSA | 容量与成本解耦是主线 |
| 多模态 | 外挂/桥接 → 原生统一 token 自回归 | 理解与生成合流，OS 级交互重构 |
| 端侧 | 不可能 → NPU 标配 + 组合拳成熟 | 隐私大于延迟大于成本 |
| Agent | 对话 → 协议化工具生态（MCP）+ 计算机操作 | 模型从"会说"到"会做"，安全成新瓶颈 |
| 对齐 | 人类反馈 → 原则化 AI 反馈 + 可验证奖励 | "环境即对齐"是下一主战场 |
| 开源格局 | 闭源领先 → 三极开源同代竞争 | 方法透明度成为新的竞争维度 |

最后回到本章的主线问题：**什么是范式级变化，什么是噪音**。判断标准可以收敛为三条——是否改变了成本曲线（如 MoE、MLA）、是否解锁了此前不可能的能力（如测试时扩展、computer use）、是否形成了自我强化的生态（如 MCP、开源衍生模型矩阵）。满足其一值得深学，三条全满足（如 RLVR、MCP）就是必须吃透的范式。

技术细节永远在变，但 15.9 节的信息过滤框架不会过时：**论文看声称、复现验真伪、博客收共识；可验证任务上的独立复现，是唯一硬通货。**
